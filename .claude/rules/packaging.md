# Packaging (build:mac) and the packaged build

**Packaging (`build:mac`): works, with a pinned patch.** electron-builder 26 loads `@noble/hashes@2` (pure ESM) through a CommonJS `require()` → `ERR_REQUIRE_ESM`, which crashes the whole packaging at startup. Worked around by turning that `require` into a dynamic `import()` in `app-builder-lib/.../blockmap/blockmap.js`. The fix is **pinned and versioned** in `patches/app-builder-lib+26.15.3.patch` (via [patch-package](https://github.com/ds300/patch-package)) and **re-applied automatically** by the `postinstall` (`patch-package`) after every `npm install`. Do not delete this `patches/` folder. If electron-builder is updated, regenerate the patch (`npx patch-package app-builder-lib`) or remove it if it is no longer needed.

**Electron ≥ 42 no longer downloads its binary on `npm install`.** After changing the `electron` version, run `npx install-electron --no` with a Node ≥ 22.12 (the package's `engines`; an older Node 22.11 crashes with `ERR_REQUIRE_ESM` on `@electron/get`): `PATH=<path to a Node ≥ 22.12>/bin:$PATH npx install-electron --no`. Without it, `node_modules/electron/dist` does not exist and `npm run dev` has nothing to launch. Moved from 41.7.0 to 44.3.0 for the upstream fix electron/electron#53257 (use-after-free of `pending_processes_` when a shared renderer was relaunched, which crashed the main process when an extension's service worker crashed). Then 44.4.1 for electron/electron#53752: in 44.3.0, the Chrome Web Store page received the real native `chrome.webstorePrivate` API, whose first call crashed the main process (null deref in `PerformSynchronousChecks`).

- Same `app-builder-lib` patch, second fix: `macPackager.js` (`doSign`) passed `codesign` the certificate's **name** even though it had just found its fingerprint. With a non-ASCII character in the certificate holder's name, `codesign --sign "<name>"` answers `no identity found` (tested by hand: by name fails, by fingerprint or by team ID passes). The patch passes `identity.hash || identity.name`. Without it, `build.sh` and the release break at signing.
- `patches/electron-chrome-web-store+0.13.0.patch`: at startup, the package swallowed the error from `startWorkerForScope` and only logged "Failed to start worker for extension <id>". The patch adds the error to the log.
- Old `postinstall` (`electron-builder install-app-deps`) removed: it crashed and served no purpose (no native dependency, `npmRebuild: false`).

**Packaged build.** `./bin/build.sh` typechecks, quits Mira **through the socket** (`bin/mira quit`) then waits until the process has really gone, runs `npm run build:mac`, then **replaces `/Applications/Mira.app` with a real copy** (`ditto` from `dist/mac-arm64/Mira.app`) and reopens the app **in the background** (`open -g -a`): a rebuild is asked for while working elsewhere, Mira must come back where it was, behind. It used to be a symlink, and that broke the macOS bundle identity: the privacy subsystems no longer found the app (`bundle_id: (null)`), hence an `ERR_ADDRESS_UNREACHABLE` on every LAN host despite the Local Network permission. The full why is at the top of `bin/build.sh`. The default dev mode remains `npm run dev` (HMR). The owner's personal rule "do not build / launch anything long-running without my consent" lives in `CLAUDE.local.md` (not versioned).

⚠️ **Never quit Mira with `osascript -e 'quit app "Mira"'` in a script.** An Apple Event reaches the confirmation gate (`src/main/quit.ts`) and raises a "Quit Mira?" modal that nobody is there to confirm; osascript returns immediately anyway, so the script chains its `rm -rf /Applications/Mira.app` onto a bundle that is still running. The socket `quit` command calls `suppressQuitPrompt()` precisely for that (`src/main/profiles.ts`, `quitApp`), as do the SIGINT/SIGTERM signals. And "the command answered ok" does not mean "the process is dead": the graceful quit flushes the sessions and re-locks the vaults, hence the wait loop on `pgrep`.

**Published release ≠ local build.** `bin/release.sh` makes a different binary: `bin/release-build.cjs` takes `electron-builder.yml` with the same "Developer ID Application" certificate, the hardened runtime, and the same Developer ID profile as the local build, `build/embedded.provisionprofile`, which authorises the keychain group: Touch ID passkeys work in the release (not yet verified on a published release). It marks it `miraDistribution: release`, then `bin/release-app.sh` checks the signature, notarises it (`notarytool`, keychain profile `mira-notary`, status read from the JSON because the exit code does not say whether Apple accepts), staples the ticket and zips it. Two zips, arm64 and x64, built on the Mac that publishes (cross-build via `MIRA_ARCH`). That binary runs on any Mac without a Gatekeeper warning and updates itself. The local build, on the other hand, is never replaced by a download. Up to 1.3.1 the release was signed ad hoc. Details: `docs/releases.md`.

⚠️ **Inspect an `app.asar` without ever extracting at the repo root.** `npx asar extract-file <asar> package.json` writes the file into the **current folder**: run from the repo, it once overwrote the repo's `package.json` with the packaged app's one (repaired from `HEAD`). To list or measure, the read-only API is enough: `require('@electron/asar').listPackage(p)` and `getRawHeader(p).header` (sizes per entry).

**Signing and provisioning profile: Developer ID.** Local build and release are signed with the "Developer ID Application: <name> (<TEAM_ID>)" certificate and embed `build/embedded.provisionprofile`, the "Mira Developer ID" Developer ID profile (all Macs). It carries the AMFI `keychain-access-groups` entitlement without which Touch ID / WebAuthn does not work (see `src/main/webauthn.ts`) and **expires with the certificate**: no more weekly renewal. A new certificate means redoing the profile. It is created on developer.apple.com (Profiles → Developer ID → Mac → the app's bundle id (`appId` in `electron-builder.yml`) → the certificate): the App Store Connect API key, Developer role, gets a 403 on `POST /v1/profiles`, but it can **download** it (`GET /v1/profiles?filter[name]=Mira Developer ID`, field `profileContent` in base64). To check: `security cms -D -i build/embedded.provisionprofile | plutil -extract Entitlements.keychain-access-groups json -o - -` must give `["<TEAM_ID>.*"]`. After a rebuild, check that the helpers are alive (`ps -Ao comm | grep -c "[M]ira Helper"` — an AMFI SIGKILL would kill them) and that `isUserVerifyingPlatformAuthenticatorAvailable()` returns `true` in a page.

**Recipe for a free account (a fork, or if the paid account goes away).** A free _personal team_ profile expires after 7 days, and Xcode **only** issues one if it signs an app that requests a capability requiring it. A project without entitlements signs fine and produces no profile (verified). Hence the recipe, with `xcodegen` (and in `electron-builder.yml`, `mac.type: development` + the Apple Development identity):

1. Throwaway macOS project, `PRODUCT_BUNDLE_IDENTIFIER: <the app's appId>`, `DEVELOPMENT_TEAM: <TEAM_ID>`, `CODE_SIGN_STYLE: Automatic`, `GENERATE_INFOPLIST_FILE: YES` (otherwise signing fails), and above all `CODE_SIGN_ENTITLEMENTS` pointing to a file that declares `keychain-access-groups = $(AppIdentifierPrefix)<the app's appId>.webauthn`.
2. `xcodegen generate` then `xcodebuild -project <p>.xcodeproj -scheme <s> -destination 'platform=macOS' -derivedDataPath <dd> -allowProvisioningUpdates build`.
3. **Clear the cache first**, otherwise step 2 renews nothing: Xcode keeps the profile in `~/Library/Developer/Xcode/UserData/Provisioning Profiles/<uuid>.provisionprofile` and **reuses it as is** while it is valid (seen in practice: rebuild at D+2, expiry unchanged). Delete/move that file then rerun step 2: Xcode issues a fresh one, new UUID, D+7.
4. The profile comes out in `<dd>/Build/Products/Debug/<App>.app/Contents/embedded.provisionprofile`. Copy it to `build/embedded.provisionprofile`, then `./bin/build.sh`.

⚠️ **`plutil -extract` only writes to stdout in `raw` format** — for any other format (`json`, `xml1`…) it writes to a **file**, whose default path is the input's. With `-` as input (stdin), it therefore creates a file literally named `-` in the current directory, returns an empty stdout and exits 0: you think the extraction was empty and you leave junk in the repo (seen in practice: a `-` file was committed then deleted). **Always `-o -`** when the format is not `raw`.

Reading trap: in an `Apple Development: <email> (<id>)` identity, the id in parentheses is the **certificate**'s identifier, not the team. The team is what `codesign -dvvv` reports as `TeamIdentifier`.
